# 行业领域需求融入原 Demo（修订版）

依据：用户提供的《河南推拿职业学院智慧专业项目研发功能交付紧急情况排序说明》Sheet1 第 2–12 行，以及用户明确要求“尽量融入原 demo 的业务”。文件中的参数是需求参考，不作为要求新建独立业务系统的指令。

## 现有页面与落点

| 原页面 | 融入方式 | 操作路径 |
| --- | --- | --- |
| 岗位画像分析 | 在原“岗位列表”标题栏增加需求量、专业匹配度、薪资排序；岗位群、等级、学历、经验、薪资筛选 | 原岗位列表顶部直接操作，岗位卡片仍打开原画像弹窗 |
| 岗位画像分析 | 复用原 24 个岗位及 8 个技术领域岗位群，聚合需求和薪资，展示对应产业环节 | 打开岗位详情→查看“所属岗位群”、产业环节与同群岗位 |
| 岗位画像分析 | 调整群成员、移动/移出、从原岗位库加入、调整预期能力覆盖率、导出群 | 岗位详情→所属岗位群→展开“调整岗位群成员与培养目标” |

| 产业链图谱 | 保留原树图、桑基图和建设建议；节点可进入相关岗位列表，补充三个行业的趋势影响 | 产业节点“查看关联岗位群”，或原图谱下方行业趋势 |

| 新岗位新技术 | 在每张原技术方向卡片内加入知识、技能、训练任务及岗位画像入口 | 展开“知识、技能与教学应用” |
| 产业企业库（智能建造等原企业表） | 原企业行增加未分类/合作/面向/优质标记及筛选，不自动判定真实合作关系 | 原企业行下拉框与列表合作分类筛选 |

已移除岗位/岗位群 Tab 切换；岗位群概况及成员维护融入岗位详情。

已删除上一版独立工作区、五个子页、专用预览入口。没有新增侧栏业务菜单。

## 数据与状态

- 岗位、薪资、需求、能力、课程分别使用 Vue 和静态入口已有数据，不再生成另一套招聘样本或能力库。
- 两个入口原先的示例数值不同，本次保持各自原始数据；不将新增人工招聘记录混入原统计。
- 已有岗位—课程关系仅表示候选课程，不等同于全部岗位能力已匹配。专业匹配度为“已确认存在课程支撑的能力项 / 全部岗位能力项”，未校准时为 0%。它是本地关系完整度，不是教学质量评价。
- 群薪资为成员岗位薪资区间中点的算术平均，不是招聘人数加权平均。
- 行业趋势、应用演进和技术教学任务是演示研判，页面已标注。没有冒充实时新闻、外部招聘抓取或已读取课程大纲。
- 群成员覆盖、目标值、能力课程关系、企业分类、人工招聘记录保存在当前浏览器来源的 `portrait-industry-integration-v2`；不改写原岗位库，不沿用上一版独立工作区的模拟数据。
- 关系导入检查能力键、课程 ID 和重复记录，整批通过后才写入。导出为 JSON。

## 尚待真实服务和资料接入的参数

课程大纲自动分析与 AI 问答、权威行业证据检索、实时企业招聘推送、区域招聘交叉筛选、能力需求权重、课件/视频/习题文件尚未连接后端或正式资料。当前用原业务内的候选关系、人工校准、教学建议和记录补充承接，不放置伪造实时结果或占位下载。

## 验证

- 构建：`npm run build`。
- 55 项相关测试：行业融入模型与入口、原岗位画像、岗位能力图谱与案例、企业列表、AI 产业链双入口。
- 浏览器在原 `view=job-research&tab=portrait` 页面验证需求排序、岗位群筛选、打开原岗位详情、课程校准后匹配排序、成员移动与恢复、新技术到岗位画像联动。
- 静态入口做脚本语法与业务入口回归校验。浏览器工具不允许直接打开 `file://`，未声称做过该协议的视觉验收。
