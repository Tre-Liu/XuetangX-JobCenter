# 产教调研报告生成 PRD

## 1. 文档信息

| 项目 | 内容 |
| --- | --- |
| 功能名称 | 产教调研报告生成 |
| 面向用户 | 专业负责人、二级学院管理者、教研人员、报告撰写人员 |
| 业务目标 | 用较少的录入工作，生成一份可预览、可追溯、可导出的专业产业调研报告，为专业建设、人才培养方案修订和校企合作提供依据。 |
| 使用入口 | 产业调研 → 报告生成 → 产教调研报告 |
| 当前范围 | 三步生成流程；只读预览与导出。 |

> 说明：当前演示版以本地模拟数据展示。本文的“数据库字段”是正式产品接入后端时应使用的业务字段，不代表演示版已连接数据库。

## 2. 背景与问题

专业调研报告通常由多份材料拼接而成：行业政策、企业调研、岗位需求、课程与就业数据分散在不同位置。编写人需要反复核对，容易出现报告范围与岗位不一致、数据来源不清楚、结论缺少依据等问题。

本功能提供统一入口：用户确定专业、产业链、区域和岗位，选择或调整目录，系统据此汇集已有数据、参考文件和 AI 生成内容。生成结果不是最终定稿，而是一份可继续编辑、审核和导出的报告草稿。

## 3. 产品目标与不做什么

### 3.1 产品目标

1. 让用户在 5 分钟内完成一份报告的范围配置。
2. 让每个报告章节都能说明使用了哪些数据。
3. 让 AI 只基于已给数据与参考材料写作；没有证据时明确提示“待补充”，不虚构。
4. 保留目录、参数、参考文件和生成版本，便于复核与再次生成。

### 3.2 本期不做

- 不把 AI 生成内容视为官方统计结论或政策文件。
- 不自动抓取互联网内容，不自动判断外部资料真伪。
- 不替代报告审核、盖章和发布流程。
- 不在本功能中建设完整的产业链、岗位、课程或企业管理后台；这些基础数据由已有模块提供。
- 不在岗位选择卡片上展示“岗位群”标注；岗位群仅作为后台关联信息和分析口径使用。

## 4. 用户角色与使用场景

| 角色 | 主要诉求 | 主要操作 |
| --- | --- | --- |
| 专业负责人 | 快速获得可用于专业建设讨论的报告初稿 | 配置范围、调整目录、审核结论、导出 |
| 教研人员 | 让报告的岗位、课程和建议贴合专业实际 | 选择岗位、上传材料、编辑章节 |
| 二级学院管理者 | 查看调研依据和改进建议是否完整 | 查看报告、追溯来源、提出修改 |
| 数据维护人员 | 保证产业链、岗位、区域等基础数据可用 | 在既有基础数据模块维护数据 |

## 5. 核心流程与交互逻辑

```mermaid
flowchart LR
  A[报告库] --> B[新建报告]
  B --> C[步骤 1：参数配置]
  C -->|校验通过| D[步骤 2：目录调整]
  D -->|校验通过| E[步骤 3：确认并生成]
  E --> F[报告预览（只读）]
  F --> G[导出、再次生成]
```

### 5.1 报告库

- 展示报告名称、专业、产业链、区域、状态、更新时间和参考文件数量。
- 用户可新建、打开、删除已有报告。
- 删除前二次确认；删除后报告、章节、已上传参考文件关联一并进入回收站，默认保留 30 天。
- 报告状态分为：草稿、生成中、待审核、已完成、生成失败。演示版可先展示草稿/已完成；正式版按完整状态流转。

### 5.2 步骤 1：参数配置

#### 5.2.1 报告名称

- 报告名称默认按“{专业}产业调研报告”带出，用户可修改。

#### 5.2.2 专业、产业链、区域

- 专业从当前专业建设上下文带入，只读显示，避免报告归属被误改。
- 产业链为单选：仅显示与该专业有关的库内产业链，并提供“自定义产业链”。
- 选择或更换产业链时，清空已选岗位和自定义岗位；提示“产业链已变更，请重新选择分析岗位”。
- 区域支持多选城市和经济区，已选区域以标签显示，可单个删除或一键清空。
- 至少选择一个区域；“全国”与具体城市/经济区不可同时选择，选择其中一个时给出替换提示。

#### 5.2.3 分析岗位

- 选择库内产业链后，仅展示与该产业链关联的岗位；一张卡片只显示岗位名称和勾选状态，不显示岗位群文字。
- 可多选库内岗位，也可输入自定义岗位并按 Enter 或“添加岗位”加入。
- 自定义产业链没有库内岗位时，仍可添加自定义岗位。
- 同名岗位只保留一项；库内岗位与自定义岗位同名时，提示“岗位名称已存在”。
- 至少选择或添加一个岗位，才可进入下一步。

#### 5.2.4 参考文件

- 支持上传与本报告有关的材料，如人才培养方案、行业调研报告、访谈纪要、企业清单、政策文件。
- 上传后显示文件名、类型、大小、上传人和解析状态；可删除未用于生成的文件。
- AI 仅可引用解析成功且已关联到当前报告的文件。

### 5.3 步骤 2：目录调整

- 用户可以修改章节名称、新增章节/小节、删除不需要的章节。
- 目录最多三级；至少保留一个一级章节；每个目录标题不能为空且去除首尾空格后不得重复。
- 用户首次进入时带入所选模板目录。若选择“自定义目录”，从一个空白一级章节开始。
- 删除含有子章节的章节时，先提示“该章节下有 N 个子章节，将一并删除”。
- 目录修改只影响当前报告，不影响公共模板。

### 5.4 步骤 3：确认并生成

- 展示报告名称、专业、产业链、区域、岗位、参考文件数量和目录摘要，供用户最后核对。
- 点击“AI 开始生成报告”后创建一个不可被当前编辑覆盖的生成快照。
- 生成中允许用户离开页面；返回后可继续查看状态。再次生成时保留旧版本，用户可选择覆盖当前草稿或另存为新版本。
- 生成成功后进入只读预览页；生成失败时说明失败原因，并提供“重试”“返回配置”“联系管理员”。

### 5.5 预览与导出

- 报告库中的“预览”入口打开只读预览页；正文、章节标题和表格均不可直接修改。
- 报告库中的“下载”直接导出当前报告的 PDF，不跳转预览页；预览页仍提供“返回报告库”“下载 PDF”“导出 ADS”，不提供编辑或保存入口。
- 每个 AI 生成章节显示“数据依据”入口，展开后可看到使用的数据类别、记录数、参考文件和生成时间。
- 导出前提示未处理风险：如“2 个章节缺少可用数据”“存在待补充标记”。用户可继续导出，但导出文件页脚注明“草稿/含待核实内容”。
- 支持导出 DOCX、PDF 和数据包（JSON/Excel）；数据包用于后续审计和再次生成。

## 6. 关键校验与边界情况

| 场景 | 产品处理 |
| --- | --- |
| 报告名称为空或仅空格 | 阻止下一步，在字段下提示“请输入报告名称”。 |
| 当前专业没有库内产业链 | 下拉框保留“自定义产业链”，并提示可自行输入。 |
| 未选产业链就选择岗位 | 不展示岗位候选，自定义岗位输入置灰，提示“请先选择产业链”。 |
| 更换产业链 | 清空所有已选岗位与自定义岗位，不自动迁移。 |
| 库内产业链没有岗位 | 显示空状态；允许继续添加自定义岗位。 |
| 自定义产业链/岗位与已有名称重复 | 按去除首尾空格后的完整名称比较，阻止添加并提示重复。 |
| 区域无匹配结果 | 显示“未找到可选区域”，不清空已选项。 |
| 上传文件类型不支持、过大或损坏 | 不进入生成范围，显示原因；其他文件不受影响。 |
| 文件解析失败 | 文件保留失败状态，可重新上传；AI 不引用该文件。 |
| 目录为空、标题为空或超过三级 | 阻止进入生成，定位到有问题的目录项。 |
| 数据不足 | 允许生成，但对应章节输出“现有数据不足，建议补充……”，并在编辑页标记待补充。 |
| 数据口径冲突 | 不由 AI 擅自取舍；章节列出冲突来源和口径差异，提示人工确认。 |
| 生成过程中重复点击 | 第二次点击无效，显示“正在生成”。 |
| 生成失败或网络中断 | 保存已配置参数和目录；不将不完整内容标为成功。 |
| 历史报告缺少新字段 | 读取旧的行业/区域文字作为展示兜底；重新保存后按新字段保存。 |
| 删除报告 | 需二次确认；已导出的文件不受影响；回收站保留 30 天。 |

## 7. 数据与字段设计

### 7.1 页面字段与主表 `research_report`

| 页面字段 | 数据库字段 | 含义 | 规则 |
| --- | --- | --- | --- |
| 报告名称 | `title` | 报告显示名称 | 必填，建议 1–100 字。 |
| 专业 | `major_id`、`major_name` | 当前报告对应专业 | 必填；页面只读。 |
| 产业链 | `industry_chain_id`、`industry_chain_name`、`industry_chain_source` | 库内或自定义产业链 | `source` 为 `library` 或 `custom`；自定义时 ID 可为空。 |
| 区域汇总 | `region_text` | 用于展示和导出 | 由区域关联记录拼接，不作为唯一数据来源。 |
| 状态 | `status` | 报告生命周期状态 | 草稿、生成中、待审核、已完成、生成失败。 |
| 当前版本 | `current_version_no` | 当前可编辑版本号 | 每次生成成功递增。 |
| 创建/更新人 | `created_by`、`updated_by` | 操作人 | 由登录用户写入。 |
| 创建/更新时间 | `created_at`、`updated_at` | 追溯时间 | 系统写入。 |

### 7.2 报告的关联表

| 表名 | 关键字段 | 用途与规则 |
| --- | --- | --- |
| `research_report_region` | `id`、`report_id`、`region_id`、`region_name`、`region_type`、`sort_order` | 一个报告可选多个城市或经济区；`region_type` 如 city/economic_zone/nation。 |
| `research_report_job` | `id`、`report_id`、`job_id`、`job_name`、`source`、`sort_order` | 已选岗位；`source=library` 时必须有 `job_id`，`source=custom` 时 `job_id` 为空。报告范围以这里的快照名称为准。 |
| `research_report_toc` | `id`、`report_id`、`parent_id`、`title`、`level`、`sort_order` | 报告目录；最多三级。 |
| `research_report_file` | `id`、`report_id`、`file_id`、`file_name`、`file_type`、`parse_status`、`parse_error`、`uploaded_by` | 当前报告的参考文件及解析状态。 |
| `research_report_version` | `id`、`report_id`、`version_no`、`content_html`、`generation_status`、`generated_at`、`generated_by` | 保存每次生成或人工保存后的正文版本。 |
| `research_report_section` | `id`、`report_version_id`、`toc_id`、`title`、`content_html`、`source_status`、`generated_at` | 可按章节保存正文；`source_status` 标记有依据、待补充或人工修改。 |
| `research_report_evidence` | `id`、`report_section_id`、`source_type`、`source_id`、`source_name`、`field_list`、`used_at` | 章节级数据依据；`source_type` 包括岗位、企业、趋势、课程、附件、人工输入。 |
| `research_report_generation_log` | `id`、`report_version_id`、`prompt_version`、`model_name`、`input_summary`、`status`、`error_message`、`started_at`、`finished_at` | 生成过程记录，用于排障与审核；不保存用户无关的敏感原文。 |

| 数据对象 | 推荐表 | 本功能使用字段 |

| 产业链 | `industry_chain` | `id`、`name`、`major_id`、`description`、`region_scope`。 |
| 岗位 | `job` | `id`、`name`、`industry_chain_id`、`group_id`、`occupation`、`occupation_code`、`industry_node_id`。其中 `group_id` 仅用于内部分析，不在本页岗位卡展示。 |

| 岗位需求 | `job_demand_stat` | `job_id`、`region_id`、`stat_period`、`demand_count`、`growth_rate`、`salary_min`、`salary_max`、`education_requirement`。 |
| 企业 | `enterprise` | `id`、`name`、`region_id`、`industry_chain_id`、`enterprise_type`、`scale`、`business_direction`。 |
| 企业岗位/访谈 | `enterprise_job_evidence` | `enterprise_id`、`job_id`、`task_text`、`skill_text`、`source_date`、`source_file_id`。 |

| 对标专业 | `benchmark_major` | `id`、`name`、`school_name`、`region_id`、`features`、`evidence_source`。 |
| 政策与文件 | `policy_document` | `id`、`title`、`publish_org`、`publish_date`、`region_id`、`industry_chain_id`、`content_excerpt`、`source_url`。 |

## 8. 章节、数据字段与生成规则

所有章节均先读取报告范围：`major_name`、`industry_chain_name`、区域清单、岗位清单、目录标题和已解析参考文件。以下表格说明每类章节的额外数据来源；“最低要求”未满足时不得补写数字或结论。

| 章节 | 主要数据来源及字段 | 最低要求 | AI 输出重点 |
| --- | --- | --- | --- |
| 专业建设背景与概述 | `major.positioning`、`training_objective`；`policy_document.title/publish_date/content_excerpt`；参考文件摘要 | 至少专业信息或一份参考材料 | 说明调研目的、范围和方法；区分事实与调研判断。 |
| 行业分布现状 | `industry_chain.description`；`enterprise.region_id/enterprise_type/scale/business_direction`；`job_demand_stat.region_id/demand_count/stat_period` | 至少一类企业或岗位需求数据 | 描述区域产业及就业行业分布，不把样本当作全量普查。 |
| 行业发展趋势与人才需求 | `policy_document`；`job_demand_stat.demand_count/growth_rate/salary_*`；`enterprise_job_evidence.source_date` | 至少两个统计期或一份时效明确的材料 | 给出趋势、时间范围和不确定性，不编造增长率。 |
| 社会需求单位性质与公司规模 | `enterprise.enterprise_type/scale`；`enterprise_job_evidence.enterprise_id` | 企业样本数量达到配置阈值；不足则说明样本有限 | 使用分布或样本描述，写清样本量。 |
| 目标就业岗位分析 | `research_report_job.job_name`；`job.occupation/occupation_code/industry_node_id`；`job_demand_stat` | 至少一个已选岗位 | 分岗位描述需求、区域、薪酬和学历；不展示岗位群标注。 |
| 人才能力需求 | `enterprise_job_evidence.task_text/skill_text`；`job_course_relation`；参考文件 | 至少岗位任务或技能材料 | 将能力分为素质、技术、工具三类；每项能力应能对应岗位任务或课程。 |
| 专业基本情况与课程体系 | `major`；`course.name/course_type/credits/practice_hours`；`job_course_relation.relation_strength` | 专业和课程数据 | 分析课程对岗位的支撑，指出缺口，不虚构未开设课程。 |
| 人才培养成效与招生 | `major_outcome_stat` | 至少一个统计年度 | 展示统计年度、口径和变化；数据不足只写“待补充”。 |
| 同类专业与 SWOT | `benchmark_major`；专业、岗位、课程和质量数据 | 至少一个对标对象或用户上传材料 | 以证据列出优势/不足，不使用绝对化宣传语。 |
| 建设改进建议 | 上述章节已确认的缺口、`job_course_relation`、`enterprise_job_evidence` | 至少一项已确认问题 | 每条建议写“问题—行动—责任对象—预期结果—依据”。 |
| 重点区域产教融合策略 | `research_report_region`；`enterprise`；`policy_document` | 至少一个区域和一条企业/政策线索 | 按区域给出企业合作、实训项目或调研补充建议。 |
| 数据来源说明 | `research_report_evidence`；`research_report_file`；`generation_log` | 系统自动生成 | 列清数据类型、时间、覆盖范围和缺失项。 |

## 9. AIGC 生成设计

### 9.1 总体原则

1. AI 只能使用输入数据、已解析附件摘要和用户填写内容；不得使用未提供的“常识数字”补齐事实。
2. 数字、政策名称、企业名称和时间必须能在输入中找到对应依据；找不到则删除或标注“待核实”。
3. 区分“事实”“分析判断”“建议”，建议不得写成既成事实。
4. 输出使用正式、克制的中文；避免“全国领先”“显著提升”等无依据表述。
5. 每个章节末尾返回数据依据及缺口，供页面展示和人工审核。

### 9.2 通用系统提示词

```text
你是职业教育专业建设调研报告助理。请只根据【报告范围】【章节要求】【可用数据】【参考材料摘要】撰写内容。

硬性要求：
```

### 9.3 章节生成提示词模板

### 9.4 生成前输入包

每次生成以报告版本为单位组装输入包，至少包括：

```json
{
  "report": {
    "id": "报告ID",
    "title": "报告名称",
    "major_name": "专业名称",
    "industry_chain_name": "产业链名称",
    "regions": ["区域名称"],
    "jobs": ["岗位名称"],
    "version_no": 1
  },
  "chapter": {"toc_id": "目录ID", "title": "章节名称"},

```

输入包只带入当前章节需要的数据，避免把无关材料和个人信息传给模型。

## 10. 权限、隐私与内容边界

- 仅报告创建人、专业负责人和被授权成员可查看或编辑报告。
- 参考文件沿用原文件访问权限；无文件权限者不得通过报告看到原文或摘要。
- 涉及个人简历、联系方式、访谈录音转写等材料，在入库前应脱敏；AI 输入默认排除身份证号、手机号、邮箱、住址等内容。
- 生成日志保存提示词版本、数据来源标识和状态，不保存超出审计需要的附件全文。
- AI 生成文本必须标注为“AI 生成草稿”，直至人工确认并完成审核。

## 11. 验收标准

1. 用户可在同一流程完成报告范围配置、目录调整、生成、编辑和导出。
2. 选择岗位时只显示岗位名称，岗位群信息不在该选择界面显示。
3. 切换产业链后，旧岗位不会残留；自定义岗位与库内岗位不可重名。
4. 每个生成章节至少能显示数据依据或“数据不足”说明。
5. 无依据时 AI 不输出具体数字、企业、政策或确定性结论。
6. 导出文件包含报告范围、版本时间和数据来源说明；存在待补充内容时有明显标识。
7. 报告参数、目录、参考文件关联和生成版本均可追溯。

## 12. 后续迭代建议

1. 增加“数据完整度”面板，按章节提示缺少的岗位需求、企业、课程或就业数据。
2. 增加审核流：教研员初审、专业负责人确认、学院发布。
3. 支持同一报告的多区域对比和多年度趋势对比。
4. 增加引用定位：点击正文中的数据，可跳转到对应企业、岗位、附件或统计记录。
