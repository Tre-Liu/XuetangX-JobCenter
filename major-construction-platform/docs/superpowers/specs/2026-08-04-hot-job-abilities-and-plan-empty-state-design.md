# 热门岗位产业环节、岗位能力与无人培空状态设计

## 背景与目标

在现有“热门岗位分析建议”浮窗基础上补充三项能力：

1. 每个岗位明确展示其所属产业环节，避免只展示产业链名称和上中下游阶段。
2. “岗位核心能力”使用入选岗位对应的真实能力项，支持从总览进入能力清单并展开查看详情。
3. 增加“模拟无人培方案”演示状态；没有人才培养方案时，所有依赖人培数据的比对与建议模块展示统一导入提示。

本次继续保持 Vue 页面与 `index.html` 静态演示版的数据、文案和交互一致，并将最终口径同步到钉钉《热门岗位分析建议》需求文档。

## 已确认方案

岗位能力采用“总览卡片下方原位展开”方案：点击“岗位核心能力”统计卡，在统计区下方展开能力面板；能力面板按岗位分组展示能力项，点击单项继续展开详情。该方案不会遮挡报告内容，也不会让热门岗位卡片承担过多信息。

“模拟无人培方案”采用浮窗左下角固定的双态演示开关：默认处于“已有人培方案”，点击切换到“无人培方案”，再次点击恢复。

## 数据设计

### 产业环节

热门岗位数据增加 `industrySegment` 字段。字段取自数据库中已经确认的岗位—产业节点关联，不根据岗位名称临时推断，也不参与热门岗位排序。

人工智能产业链 demo 使用以下已入库产业环节：

| 产业阶段 | 产业环节 |
| --- | --- |
| 上游 | 数据、算力与模型基础 |
| 中游 | 智能感知、语音视觉与平台工具 |
| 下游 | 行业智能化应用与 AI 服务 |

岗位卡片展示“产业链名称 · 产业阶段”，并另起一项明确标注“产业环节：完整环节名称”。市场热门岗与产业代表岗的入选标签保持不变。

### 岗位能力

每个入选岗位增加 `abilities` 能力项数组。能力项由数据库中该标准岗位对应的岗位职责、工作任务和能力要求整理，禁止使用与岗位无关的通用占位文案。每项包含：

- `id`：稳定标识，用于展开状态与去重。
- `name`：能力名称。
- `type`：知识、技能或素养。
- `description`：能力定义。
- `tasks`：该能力对应的典型工作任务。
- `source`：能力来源说明，至少能追溯到关联标准岗位或岗位职责。

“岗位核心能力”统计值根据当前入选岗位的能力项按 `id` 去重后实时计算，不再使用固定的“6项”。能力面板默认折叠；展开后按岗位分组，岗位组内展示能力名称和类型。能力项详情默认折叠，点击后展示能力定义、典型工作任务和来源。

同一能力可关联多个岗位；总数去重，但在每个相关岗位分组中都可以查看。切换热门岗位分页不改变能力总览范围，能力面板始终对应本次分析全部入选岗位，而不是只统计当前页的 6 个岗位。

## 交互设计

### 岗位卡片

岗位卡片的信息顺序为：

1. 岗位名称。
2. 产业链名称与产业阶段。
3. 产业环节。
4. 入选类型标签。

产业环节文案允许换行，不以省略号隐藏核心名称。分页规则与原有热门岗位设计保持一致。

### 岗位核心能力

“岗位核心能力”统计卡改为可点击控件，提供可见的展开提示，并使用 `aria-expanded` 表示状态。点击后在统计区和专业分析摘要之间展开能力面板；再次点击收起。

能力项行也是可点击控件，使用独立的 `aria-expanded`。一次可展开多个能力项，方便横向比较；关闭并重新打开整个分析浮窗时恢复为全部折叠状态。

### 模拟人培方案状态

浮窗左下角固定一个不随报告内容滚动的演示开关：

- 默认状态文案：“模拟：已有人培方案”。
- 无人培状态文案：“模拟：无人培方案”。
- 切换时只改变依赖人才培养方案的模块，不关闭浮窗、不改变热门岗位页码和当前分析页签。
- 关闭并重新打开浮窗时恢复默认的“已有人培方案”状态，保证每次演示起点一致。

演示开关属于 demo 辅助控件，不进入正式业务信息层级；视觉上使用弱强调的小尺寸按钮，并避免遮挡浮窗内容和浏览器滚动条。

## 无人培方案空状态

无人培状态下，以下六个依赖人才培养方案的模块不展示模拟分析结论，统一替换为空状态：

1. 培养目标对比分析。
2. 新增目标建议。
3. 毕业要求比对分析。
4. 新增毕业要求建议。
5. 课程支撑度明细。
6. 新增课程建议。

统一提示文案为：

> 没有人才培养方案数据，请先导入人才培养方案

空状态保留原模块标题，使用户能理解当前缺失的是哪项分析；正文区域显示统一提示。热门岗位、产业环节、岗位核心能力、专业分析摘要和不依赖人培数据的岗位侧分析继续正常展示。

本期只模拟状态和提示，不在浮窗内实现真实上传、解析或导入流程，也不自动生成一份虚拟人才培养方案。

## Vue 与静态版状态

Vue 页面新增：

- 人培方案是否存在的布尔状态，默认 `true`。
- 岗位能力面板展开状态。
- 已展开能力项 ID 集合。
- 从全部入选岗位能力项计算得到的去重能力总数。

静态演示版维护同等状态，并在重新渲染报告内容时保留当前人培状态、页签和能力展开状态。两种实现使用相同的字段名、文案和数据顺序。

## 边界与异常

- 岗位缺少产业环节关联时不凭名称猜测；显示“产业环节：待确认”，并在数据校验中记录。
- 岗位没有能力项时显示“暂无已关联能力项”，该岗位不贡献能力总数。
- 能力项缺少详情字段时仍可展示名称和类型，但展开区明确显示“暂无详情”，不使用编造内容补齐。
- 无人培状态下不得继续展示上一次有人培状态的对比结论或建议。
- 在无人培与有人培之间来回切换时，不修改热门岗位数据、产业环节和岗位能力数据。
- 产业代表岗与市场热门岗均可展示产业环节和真实能力项；入选类型不影响能力展示。

## 测试与验收

采用测试先行，先增加预期并确认因功能缺失而失败，再实现 Vue 和静态版。

自动化检查覆盖：

- 每个热门岗位数据包含产业阶段和完整产业环节。
- Vue 与静态岗位卡片都明确显示“产业环节”。
- 入选岗位包含可追溯的能力项数据，能力总数由数据去重计算而非硬编码。
- “岗位核心能力”统计卡可以展开、收起，并具有正确的 `aria-expanded`。
- 能力项可以独立展开，详情包含能力定义、典型工作任务和来源。
- 能力总数覆盖全部入选岗位，不受当前分页影响。
- 浮窗左下角存在双态人培模拟开关，默认处于“已有人培方案”。
- 切换到无人培状态后，六个指定模块均展示统一提示，不显示模拟比对结果或建议。
- 无人培状态不影响热门岗位、产业环节、岗位能力和不依赖人培的分析内容。
- 恢复有人培状态后六个模块重新显示原分析内容。
- 关闭再打开浮窗时，人培状态和能力展开状态回到默认值。
- 聚焦测试、完整测试集与生产构建均通过。

视觉验收覆盖桌面弹窗长页面场景：产业环节可完整阅读；能力面板层级清晰；左下角模拟开关不遮挡正文；六个空状态在三个页签下使用一致的视觉样式和文案。

## 需求文档同步位置

功能验证通过后，将本设计融入钉钉《热门岗位分析建议》现有章节，不新增孤立的补充需求章节：

- 热门岗位总览：补充产业环节字段与展示规则。
- 岗位能力分析：补充真实能力来源、去重口径和展开交互。
- 培养目标、毕业要求、课程建设分析：分别补充无人培方案空状态。
- Demo 说明：补充左下角双态演示开关。
- 验收标准：补充产业环节、能力详情和六个空状态的验收项。
