# 从岗位工作任务到学习型工作任务

本文件依据用户提供的《20240704职业教育-工作任务.docx》分析概念，并记录 AI 课程原型的产品转化方案。附件是研究材料，其中批注与建议不视为用户指令。

## 1. 是否存在“学习型工作任务”的定义

**存在明确表述。** 附件在“设计开发‘学习型工作任务’的方法”中指出：源自职业岗位工作过程的典型工作任务，经分析、归纳和教学论处理，转化为职业学校实习、实训中可以实施的学习型工作任务。该段标注文献 [6]：汤百智、汤棣华《基于工作过程取向的职业教育专业课程组织研究》，2015。

附件引用文献 [3]（李晓东、师伟《论职业教育课程中的“学习型”任务》，2021）也明确提出：真实工作任务经过“教学性”改造、置于学习情境，形成“学习型”任务；“问题”是其核心，学习在问题的展开、深化和解决中发生。

因此，本产品可采用的工作定义是：**源于真实职业任务，依据课程目标、学习者水平和教学条件进行教学化处理，以核心问题驱动、以完整工作行动组织，并通过成果和过程证据评价学习的任务。** 这是依据附件的综合表述，不冒充某一文件的逐字定义，也不称为统一国家标准。

科学出版社《职业教育课程与教学论》的官方目录也设有“专业教学中‘学习型工作任务’的设计”一节，印证该术语的使用：[出版社页面](https://www.ecsponline.com/goods.php?id=173762)。本次未据此推定国家标准效力。

## 2. 概念边界与产品映射

| 对象 | 含义 | 原型中的组织方式 |
| --- | --- | --- |
| 典型工作任务 | 工作过程结构完整的综合性职业任务，须通过职业实践分析获得 | 来源任务，保留岗位、任务编号和证据 |
| 岗位能力项 | 完成任务所需的知识、技能、素养 | 原子能力，保留编号并关联学习活动 |
| 学习型工作任务 | 经过教学化处理的任务 | 项目中的学习情境与活动组织 |
| 项目 | 以产品或服务成果承载完整工作的教学载体 | 项目说明、阶段、学习活动与评价 |

**项目可以承载学习型工作任务，但两者不是无条件同义，也不是固定一一对应。** 附件明确提出循环式、分段式、对应式等任务—项目匹配方式，且指出一个典型工作任务一般可作为一门课程，由一个或若干学习任务组成。本期使用“从一个来源任务设计一个具体学习情境”的有限入口；不把它设定为长期数据模型的唯一关系。

## 3. 自动转化方法

1. **确定来源与边界。** 获取同专业的人培、岗位、典型任务与相关能力，保留学校、专业、文件、定位和原编号；缺少岗位时建立独立的生成草稿，不能自动变成已证实的真实岗位资料。
2. **对照课程目标与学情。** 填写课程学习目标、先备知识、学生水平和课时，选择基础型、综合型或创新型任务。
3. **重构学习情境。** 保留工作逻辑，调整工作对象、内容、手段、组织、产品、环境六要素。例如工业产线操作转成校内机器人工作站训练，缩小工作规模并先仿真后实操。
4. **设计核心问题。** 把岗位要求转化为需要获取信息、做出取舍并用证据回答的问题，而非只有操作步骤或知识问答。
5. **组织完整行动。** 本模板使用“明确任务与获取信息—计划—决策—实施—检查—评价反馈”；为各阶段提出引导问题、提交成果、评价依据，并关联能力编号。
6. **调整支架与迁移。** 基础型给出明确引导；综合型增加跨环节整合、减少提示；创新型开放目标与验证路径。类型切换自动调整支持和迁移建议，教师可修改。
7. **审阅后建项目。** 教师检查可行性、覆盖性、真实性、代表性、趣味性、挑战性、跨界性、教育性，再创建可编辑草稿。检查项是人工判断，不提供虚构质量分或覆盖百分比。

附件不同部分列有不同的阶段数量和“计划／决策”先后；完整行动是原则，六阶段模板不是每个岗位唯一的教学顺序。附件中的“三个以上学习情境”针对特定的工作过程系统化课程设计，不应要求每个项目都强制生成三个情境。

## 4. 前置条件与异常分支

| 状态 | 原型行为 |
| --- | --- |
| 课程未关联专业 | 提示完成关联，阻止进入岗位选择 |
| 无人培或人培专业不一致 | 提示配置同专业方案，阻止进入岗位选择 |
| 产教模型未启用 | 提示启用，阻止进入岗位选择 |
| 条件齐备且存在相关岗位 | 按专业、人培过滤，选择任务与能力 |
| 条件齐备但无相应岗位／搜索无结果 | 允许手动补充岗位、主要工作及能力草稿 |
| 人培缺少某一类能力 | 明示缺口，不补造人培原文 |
| 来源或教学内容变化 | 清除审阅确认，重新生成预览 |
| 教师确认 | 新建项目，不覆盖已有项目 |

当前配置是本地原型。默认未关联；示例按钮加载工业机器人技术专业、许昌职业技术学院 2025 级人培和模拟启用状态，不表示当前课程真实关联该学校。示例岗位名是历史匹配结果，界面同时保留来源岗位“工业机器人操作与运维类岗位”，有待业务复核。

## 5. 本期实现与后续接入边界

已实现：四步向导、前置条件校验、样本岗位任务与原子能力选择、未找到岗位时的补充入口、可编辑辅助能力草稿、三类任务、六要素、学情／课程目标／核心问题／成果／评价设计、自动阶段草稿、教师确认、创建新项目、本地保存、学习者预览、离线入口同步。

当前生成引擎为本地规则，**未连接在线 AI 或真实专业建设后端**。手动岗位分支的任务与能力是启发式辅助草稿，必须补充调研并复核；参考数据仅包含一个岗位下的一项任务及六项能力，是流程样本而非完整岗位库。自动课时与能力映射为建议，来源能力类别也沿用历史抽取，需教师复核。

后续正式接入应提供：课程关联状态及版本；按专业与人培版本过滤的岗位、任务、能力接口；AI 结构化生成接口（草稿来源与模型版本）；教师修订、审核记录；课程标准目标／知识图谱的实际映射。AI 返回内容仍必须经过相同前置条件、来源编号、字段完整性与人工确认校验。
