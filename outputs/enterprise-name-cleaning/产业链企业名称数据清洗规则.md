# 产业链企业名称数据清洗规则

## 1. 文档说明

- 文档版本：V1.0
- 编制日期：2026-08-11
- 适用数据：`2025年最新产业链企业相关数据`目录中的产业链企业主表及基础信息表
- 适用环节：原始数据入库、企业主数据归一、产业链关联、企业库查询与展示
- 核心原则：保留原始数据、信用代码优先、异常分级处理、禁止直接物理删除

本文档用于识别和处理企业名称字段中的无效名称、信用代码误填、纯数字名称、经营状态混入、曾用名混入及同一主体多名称等问题。

## 3. 清洗目标

清洗完成后，每条企业记录应至少形成以下结果：

1. 保留未经修改的原始企业名称。
2. 生成可用于检索、展示和关联的标准企业名称。
3. 将信用代码、曾用名和状态说明从名称字段中拆出。
4. 标识名称质量、经营状态和是否需要人工审核。
5. 使用统一社会信用代码归并跨产业链重复企业。
6. 非正常主体保留历史记录，但默认不进入有效企业库视图。

## 5. 清洗处理顺序

规则必须按以下顺序执行，避免前后规则互相覆盖：

1. 保留原始值及来源信息。
2. 字符级标准化。
3. 提取信用代码。
4. 识别强异常名称。
5. 拆分曾用名和状态备注。
6. 标准化经营状态。
7. 生成名称匹配键。
8. 按信用代码归并企业主体。
9. 处理同一主体多名称冲突。
10. 输出有效、隐藏、隔离和待复核数据集。

## 6. 字符级标准化规则

字符标准化只生成新字段，不修改`raw_company_name`。

### 6.1 自动处理

- 使用Unicode NFKC进行全角、半角规范化。
- 删除首尾空格。
- 删除换行、制表符、零宽空格、BOM和不可见控制字符。
- 将连续空白合并为一个普通空格。
- 将中文括号统一为半角括号，或在全库中统一为中文括号。
- 统一常见连接符、引号和中英文标点。
- 英文字母统一大小写仅用于匹配键，不改变展示名称。

### 6.2 不建议自动处理

- 不直接删除名称内部所有空格，外资企业名称可能合法包含空格。
- 不直接删除括号，括号可能是合法名称组成部分，如`联检(山东)科技有限公司`。
- 不进行简繁体强制转换，避免改变工商登记名称。

## 7. 强异常名称规则

命中以下任一规则时，设置：

```text
name_quality_status = INVALID
record_action = QUARANTINE
manual_review_required = true
```

隔离表示不进入企业名称检索、展示和统计，但原始主体记录仍需保留。

### 7.1 空值和占位符

匹配以下值：

```regex
^(?:[-—–_/\\.·*]+|无|暂无|未知|未公开|未披露|空|null|none|n/?a|nan|0)$
```

匹配时不区分英文大小写。

### 7.2 信用代码或注册号误填名称

典型异常：

```text
91371423MA3F8CG55G
914401063044494056
```

建议规则：

```regex
^[0-9A-Z]{18}$
^\d{15}$
^\d{18}$
```

处理方式：

1. 对18位字符串执行统一社会信用代码格式及校验位校验。
2. 如果名称值与`credit_code`相同，则将名称置空并标记`CREDIT_CODE_AS_NAME`。
3. 如果信用代码字段为空，可将合法代码回填到`credit_code`。
4. 不得把信用代码继续作为企业展示名称。

### 7.3 纯数字名称

建议规则：

```regex
^\d+(?:\.0+)?$
```

仅当整个名称字段都是数字时才判定异常。以下情况不得误删：

```text
360安全科技股份有限公司
58同城信息技术有限公司
一二三数字科技有限公司
```

### 7.4 法院或登记机关认定名称不适宜

应识别以下关键词组合：

```text
企业名称已被人民法院认定不适宜
企业名称已被登记机关认定为不适宜
名称已被认定应当停止使用
名称已被认定为不适宜
```

推荐规则：

```regex
(?:企业)?名称.*?(?:人民法院|登记机关).*?(?:不适宜|不予使用|停止使用|认定)
```

典型记录：

```text
91440300053864005T(企业名称已被人民法院认定不适宜)
```

处理结果：

```text
credit_code = 91440300053864005T
company_name_clean = NULL
name_quality_status = INVALID
invalid_reason = JUDICIAL_NAME_INVALID
record_action = QUARANTINE
```

该主体登记状态即使显示为`存续`，也不能继续展示此名称。应根据统一社会信用代码重新获取现行名称；无法获取时维持隔离状态。

### 7.5 电话、邮箱和网址误填

参考规则：

```regex
^(?:\+?86[- ]?)?(?:1[3-9]\d{9}|0\d{2,3}[- ]?\d{7,8})$
(?:https?://|www\.)
@[a-z0-9.-]+\.[a-z]{2,}
```

### 7.6 乱码、截断和不可识别字符

以下情况进入隔离或人工复核：

- 包含替换字符`�`。
- 包含典型乱码，如`锟斤拷`。
- 连续出现三个及以上问号。
- 左右括号数量不一致。
- 名称明显截断在“有限公司企”“企业名称已”等不完整词组处。
- 名称超过100个字符且包含说明性文本。

## 8. 名称附加信息拆分规则

### 8.1 曾用名

原始值：

```text
泰州市华志珹智能科技有限公司(曾用名:江苏华志珹智能科技有限公司)
```

拆分结果：

```text
company_name_clean = 泰州市华志珹智能科技有限公司
former_company_name = 江苏华志珹智能科技有限公司
name_quality_status = CLEANED
record_action = KEEP_CLEANED
```

参考规则：

```regex
^(.*?)[（(]\s*曾用名\s*[:：]\s*(.*?)[）)]$
```

若包含多个曾用名，应按逗号、分号进行拆分，并保留原始顺序和来源时间。

### 8.2 状态说明混入名称

需要识别的词语包括：

```text
已注销
吊销
已强制除名
已除名
破产清算
责令关闭
已告解散
证书废止
迁出
歇业
```

示例：

```text
兖矿峄山化工有限公司(破产清算)
(已除名)(曾用名:忠县陶乐居老年公寓)
91370700MA3RAC6K6B(已强制除名)
```

处理原则：

- 有完整合法名称时，将状态说明拆入`name_status_note`。
- 名称只剩状态说明时，将标准名称置空并隔离。
- 名称状态和登记状态冲突时，设置`manual_review_required = true`。

## 9. 经营状态标准化规则

### 9.1 正常经营

以下状态归入`ACTIVE`：

```text
存续
开业
在业
正常
在营
在册
仍注册
```

输出：

```text
registration_status_group = ACTIVE
is_active = true
```

### 9.2 非正常经营

以下状态归入`INACTIVE`：

```text
注销及带注销日期的状态
吊销
吊销,未注销
吊销,已注销
撤销
迁出
责令关闭
歇业或已歇业
已告解散
证书废止
除名
```

参考规则：

```regex
(注销|吊销|撤销|迁出|责令关闭|歇业|已告解散|证书废止|除名)
```

输出：

```text
registration_status_group = INACTIVE
is_active = false
record_action = HIDE
```

非正常企业不建议物理删除，应保留在历史库及产业链关系历史表中，但默认不进入有效企业列表、企业数量统计和推荐结果。

### 9.3 未知状态

以下状态归入`UNKNOWN`：

```text
空值
-
其他
无法映射的新状态
```

输出：

```text
registration_status_group = UNKNOWN
is_active = NULL
record_action = REVIEW
```

未知状态不得直接当作正常经营。

## 10. 弱异常与人工复核规则

以下规则只用于生成复核任务，不应自动删除记录。

### 10.1 缺少企业组织形式后缀

不能仅以“不包含有限公司”作为无效判定，因为合法主体可能是：

```text
网吧
药房
医院
公寓
管理处
工程处
合作社
合伙企业
研究院
事务所
家庭农场
个体工商户
分公司
营业部
银行或支行
```

只有在名称非常短、缺少信用代码、缺少地区及主体信息时，才进入人工复核。

### 10.2 纯外文名称

纯英文或英文数字名称不能直接删除。若存在有效信用代码、登记状态、注册地址或外资企业类型，应保留并人工核验中文登记名称。

### 10.3 名称过短或异常过长

- 仅1个字符：人工复核。
- 2至3个字符：结合信用代码和组织形式判断。
- 超过100个字符：检查是否混入简介、地址、状态或其他说明。

## 11. 企业主体去重规则

### 11.1 主键优先级

企业归并键按以下优先级生成：

1. 校验通过的统一社会信用代码。
2. 旧15位工商注册号与信用代码映射结果。
3. 标准化企业名称＋省份＋城市＋法定代表人。
4. 标准化企业名称＋注册地址。

禁止只按企业名称去重。

### 11.2 同一信用代码多个名称

本次扫描发现295个统一社会信用代码对应多个名称。处理原则：

1. 优先使用最新核准日期或最新数据批次中的名称。
2. 名称包含`曾用名:`时，拆出曾用名后再比较。
3. 旧名称写入企业名称历史表，不覆盖删除。
4. 同一信用代码在同一时间出现两个完全不同的现行名称时，进入人工核验。
5. 跨产业链出现同一主体时，仅保留一个企业主记录，产业链关系写入关系表。

### 11.3 缺少信用代码

缺少信用代码时生成临时匹配键：

```text
normalized_name + province + city + legal_representative
```

名称相同但注册地址、法定代表人明显不同的主体不得自动合并。

## 12. 名称匹配键生成规则

`company_name_normalized`仅用于检索和匹配，不用于用户展示。建议处理：

1. NFKC标准化。
2. 转为小写。
3. 删除空格和常见中英文标点。
4. 统一`有限责任公司`与`有限公司`仅作为辅助匹配特征，不直接替换工商名称。
5. 保留地区、字号和行业关键词。

示例：

```text
原名称：联检（山东）科技有限公司
匹配键：联检山东科技有限公司
```

## 13. 清洗结果分层

| 数据层 | 条件 | 用途 |
| --- | --- | --- |
| 有效企业层 | 名称有效且经营状态正常 | 企业库展示、检索、统计、推荐 |
| 清洗保留层 | 名称经曾用名或备注拆分后有效 | 企业库展示及检索 |
| 非正常企业层 | 名称有效但经营状态非正常 | 历史查询，不计入有效企业数 |
| 隔离层 | 信用代码当名称、司法认定不适宜、占位符、乱码 | 等待回查修复，不对外展示 |
| 待复核层 | 状态缺失、纯外文、名称过短、多名称冲突 | 人工核验 |

## 14. 推荐异常原因代码

| 代码 | 含义 |
| --- | --- |
| `EMPTY_OR_PLACEHOLDER` | 空值或占位符 |
| `CREDIT_CODE_AS_NAME` | 信用代码或注册号误填名称 |
| `NUMERIC_ONLY_NAME` | 纯数字名称 |
| `JUDICIAL_NAME_INVALID` | 法院认定名称不适宜 |
| `REGISTRY_NAME_INVALID` | 登记机关认定名称不适宜或停止使用 |
| `STATUS_TEXT_AS_NAME` | 名称仅包含状态说明 |
| `STATUS_MIXED_IN_NAME` | 名称混入注销、除名、清算等状态 |
| `FORMER_NAME_MIXED` | 当前名称混入曾用名备注 |
| `URL_EMAIL_PHONE_AS_NAME` | 网址、邮箱或电话误填名称 |
| `GARBLED_TEXT` | 乱码或不可识别字符 |
| `TRUNCATED_NAME` | 名称疑似被截断 |
| `UNBALANCED_BRACKETS` | 括号不匹配 |
| `INACTIVE_REGISTRATION` | 非正常经营状态 |
| `UNKNOWN_REGISTRATION_STATUS` | 登记状态缺失或未知 |
| `MULTIPLE_NAMES_FOR_CREDIT_CODE` | 同一信用代码对应多个现行名称 |
| `MISSING_LEGAL_FORM_REVIEW` | 缺少常见组织形式，需复核 |
| `FOREIGN_NAME_REVIEW` | 纯外文名称，需复核 |

## 15. 规则伪代码

```text
for record in source_records:
    preserve raw_company_name and source location

    normalized_text = normalize_unicode_and_whitespace(raw_company_name)
    extracted_credit_code = extract_credit_code(normalized_text)

    if credit_code is empty and extracted_credit_code is valid:
        credit_code = extracted_credit_code

    if is_placeholder(normalized_text):
        quarantine(EMPTY_OR_PLACEHOLDER)
    elif is_credit_code_or_registration_number(normalized_text):
        quarantine(CREDIT_CODE_AS_NAME)
    elif contains_judicial_or_registry_invalid_notice(normalized_text):
        quarantine(JUDICIAL_NAME_INVALID or REGISTRY_NAME_INVALID)
    elif is_phone_email_or_url(normalized_text):
        quarantine(URL_EMAIL_PHONE_AS_NAME)
    else:
        company_name_clean, former_names, status_note = split_name_metadata(normalized_text)
        validate_name_structure(company_name_clean)

    registration_status_group = map_registration_status(registration_status_raw)

    if registration_status_group == INACTIVE:
        record_action = HIDE
    elif registration_status_group == UNKNOWN:
        manual_review_required = true

    company_key = validated_credit_code
        or composite_key(company_name_normalized, province, city, legal_representative)

merge records by company_key
retain all source and name history
```

## 16. 验收标准

清洗任务完成后应满足：

1. 原始名称和来源位置100%可追溯。
2. 18位信用代码不再作为企业展示名称。
3. 纯数字名称、占位符和司法认定不适宜名称不进入有效企业视图。
4. 曾用名从当前名称中拆出并保留历史关系。
5. 注销、吊销、撤销等非正常企业默认不计入有效企业数量。
6. 同一有效信用代码在企业主表中只保留一个主体。
7. 同一企业可以关联多个产业链、产业环节和来源文件。
8. 空状态、名称冲突和弱异常均生成可追踪的人工复核任务。
9. 所有自动规则必须提供命中原因代码。
10. 清洗前后记录数量、隔离数量、隐藏数量和合并数量可核对。

## 17. 建议输出统计

每次清洗批次应输出：

- 输入记录数。
- 有效企业主体数。
- 正常经营主体数。
- 非正常经营主体数。
- 名称自动清洗数。
- 名称隔离数。
- 待人工复核数。
- 信用代码归并数。
- 同一信用代码名称冲突数。
- 各异常原因代码数量。
- 各来源工作簿异常数量。
