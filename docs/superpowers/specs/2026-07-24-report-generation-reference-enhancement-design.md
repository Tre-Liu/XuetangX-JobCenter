# 报告生成参考系统增强设计

## 1. 背景

当前“调研报告生成”模块已经具备报告库、三步创建向导、三级目录编辑、生成进度、正文编辑、PDF 导出和 ADS 导出能力。创建流程目前只采集报告标题、报告类型、产业方向和参考文件，无法明确表达报告面向的专业、行业、区域与岗位范围，也没有区分自定义目录和模板目录。

参考系统的“专业分析报告”创建页提供了报告类型、专业、相关行业、指定区域、分析岗位以及自定义/模板创建方式。此次增强吸收这些业务参数，但保留当前系统更清晰的三步向导、现有视觉体系和报告编辑导出能力。

## 2. 目标

- 补齐报告生成所需的专业、行业、区域和岗位范围。
- 让“自定义”和“按模板创建”产生明确不同的目录初始化行为。
- 在生成前完整确认参数、岗位、模板和目录。
- 让关键配置进入报告元数据、正文摘要和 ADS 导出内容。
- 保持 Vue 应用入口和支持 `file://` 的静态入口行为一致。

## 3. 非目标

- 不建设独立的报告模板管理后台。
- 不新增后端接口或真实 AI 生成服务。
- 不重做报告库、报告编辑器、PDF 导出和 ADS 导出的整体界面。
- 不复制参考系统的旧版视觉样式和一页式创建布局。
- 不修改产业调研、岗位建设中心等其他业务模块。

## 4. 方案选择

采用“增强现有三步向导”方案。

保留当前 `参数配置 → 目录调整 → 报告生成` 的流程，在第一步扩充业务参数，在第二步根据创建方式初始化目录，在第三步完整展示生成范围。相比复刻参考系统的一页式表单，该方案能保留当前流程的清晰度；相比建设完整配置中心，该方案范围可控，能够利用现有前端数据完成演示。

## 5. 用户流程

### 5.1 新建报告

1. 用户从报告库点击“新建报告”。
2. 系统打开第一步“参数配置”，并填入当前专业、当前产业链和默认区域。
3. 用户选择报告类型、专业、相关行业、区域、分析岗位、创建方式和可选参考文件。
4. 系统校验参数。通过后进入第二步。
5. 模板模式加载所选模板目录；自定义模式显示一个空白一级章节。
6. 用户编辑三级目录后进入第三步。
7. 系统汇总展示所有生成参数和目录摘要。
8. 用户点击“AI 开始生成报告”，进入生成进度页。
9. 生成完成后，系统在报告库创建一条草稿记录并进入可编辑报告页。
10. 用户首次保存后，报告状态更新为“已完成”，之后可继续编辑、预览和导出。

### 5.2 返回修改

- 从第二步或第三步返回时，已经填写的表单、选择的岗位、参考文件和目录保持不变。
- 从编辑页点击“返回配置”时进入第三步，便于核对当前生成配置。
- 用户修改不会影响报告库中的既有报告，直到生成流程完成。
- 新建报告在生成成功前不写入报告库，避免失败任务留下无效记录。

### 5.3 模板切换

- 第一次进入第二步时，系统按创建方式初始化目录。
- 模板模式下，如果用户修改目录后再更换模板，系统显示覆盖确认。
- 用户确认后用新模板替换当前目录；取消后保留当前目录和原模板选择。
- 自定义模式从一个标题为“新增章节”的一级章节开始，不自动混入模板章节。

## 6. 参数配置

### 6.1 字段

| 字段 | 控件 | 规则 |
| --- | --- | --- |
| 报告名称 | 单行输入框 | 必填，去除首尾空格后不能为空 |
| 报告类型 | 单选 | `专业报告`、`行业报告` |
| 选择专业 | 单选下拉 | 专业报告必填；行业报告可选 |
| 相关行业 | 单行输入框 | 必填 |
| 指定区域 | 单选下拉 | 必填 |
| 分析岗位 | 多选选择器 | 必填，最多 10 个 |
| 创建方式 | 单选 | `自定义`、`按模板创建` |
| 报告模板 | 单选下拉 | 仅模板模式显示且必填 |
| 参考文件 | 多文件上传 | 可选，沿用现有文件选择能力 |

### 6.2 默认值

- 报告名称：沿用当前默认报告名称。
- 报告类型：默认选择“专业报告”。
- 专业：默认选择当前专业。
- 相关行业：由当前产业链名称推导，用户可修改。
- 区域：沿用当前默认区域。
- 岗位：默认不选择，要求用户明确生成范围。
- 创建方式：默认选择“按模板创建”。
- 模板：默认选择与报告类型匹配的首个模板。

### 6.3 校验

- 报告名称为空时提示“请输入报告名称”。
- 专业报告未选择专业时提示“请选择专业”。
- 相关行业为空时提示“请输入相关行业”。
- 未选择区域时提示“请选择指定区域”。
- 未选择岗位时提示“请至少选择一个分析岗位”。
- 岗位达到 10 个后禁用其余候选项，并提示“最多选择 10 个分析岗位”。
- 模板模式未选择模板时提示“请选择报告模板”。
- 校验错误显示在对应字段附近，并在页面底部保留汇总错误提示。

## 7. 报告模板

本次使用本地配置定义模板，不增加模板管理后台。模板至少包括：

- 专业分析报告模板：用于专业报告，目录聚焦专业背景、产业与岗位需求、专业现状、竞争力和建设建议。
- 行业分析报告模板：用于行业报告，目录聚焦行业概况、区域产业、企业与岗位需求、技术趋势和人才培养建议。

每个模板包含唯一标识、名称、适用报告类型、说明和三级目录结构。模板目录复用现有 `ReportTocItem` 结构。

## 8. 目录调整

- 继续支持三级目录。
- 支持新增一级章节、二级小节和三级条目。
- 支持直接修改标题和删除节点。
- 至少保留一个一级章节。
- 所有目录标题去除首尾空格后不能为空。
- 模板模式在目录页显示当前模板名称。
- 自定义模式显示“自定义目录”标识。
- 进入第三步前校验目录结构，定位并提示第一个空标题。

## 9. 生成确认

第三步分为三类信息：

### 9.1 报告信息

- 报告名称
- 报告类型
- 专业
- 相关行业
- 指定区域
- 创建方式与模板
- 参考文件数量

### 9.2 分析范围

- 已选岗位数量
- 已选岗位标签，最多直接展示 10 个

### 9.3 目录摘要

- 一级章节、二级小节和三级条目数量
- 前两个一级章节名称
- “查看全部”按钮返回第二步

## 10. 生成与结果

### 10.1 生成状态

- 点击生成后锁定按钮，防止重复触发。
- 生成页说明正在整合专业、行业、区域、岗位、参考文件和目录。
- 演示环境继续使用前端延迟模拟生成。
- 生成失败时显示错误状态，提供“重新生成”和“返回配置”。
- 生成成功时创建新的草稿报告记录；同一次生成重试不得重复创建记录。

### 10.2 动态报告内容

现有演示正文继续作为内容基础，但生成结果必须动态更新：

- 报告主标题。
- 报告副标题中的专业、行业、区域和生成日期。
- 摘要中的分析岗位范围与创建方式。
- 岗位需求相关段落中的已选岗位名称。
- 数据来源说明中的参考文件数量。

动态内容由纯函数根据表单、岗位和目录数据生成，避免在模板中直接拼接分散状态。

### 10.3 编辑与导出

- 保留正文 `contenteditable` 编辑。
- 保留保存时间和字数统计；新报告首次保存后由草稿更新为已完成。
- 保留 PDF 预览与下载。
- 保留 ADS 导出。
- ADS 元数据新增专业、相关行业、区域、岗位列表、创建方式、模板标识和参考文件数量。

## 11. 报告库

### 11.1 数据结构

报告记录新增：

- `reportKind`：专业报告或行业报告。
- `major`：关联专业，可为空。
- `relatedIndustry`：相关行业。
- `region`：指定区域。
- `jobIds`：分析岗位标识列表。
- `creationMode`：自定义或模板。
- `templateId`：模板标识，可为空。
- `referenceFileCount`：参考文件数量。
- `toc`：生成时确认的目录结构。

### 11.2 列表与操作

- 报告库保留现有统计、搜索和列表。
- 列表使用紧凑标签展示“专业报告/行业报告”和“模板/自定义”。
- 搜索范围加入专业、相关行业、区域和岗位名称。
- 复制报告时复制完整配置，但新记录状态为草稿。
- 编辑既有报告时恢复其完整参数与目录。
- 新报告生成成功后加入报告库并标记为草稿，首次保存后标记为已完成。

## 12. 状态与数据流

扩展当前 `reportForm`，由单一表单状态保存创建参数。岗位仅保存稳定标识，显示名称通过现有岗位数据映射得到。

目录状态继续使用 `reportTocRows`。新增目录来源状态，用于区分：

- 尚未初始化；
- 来源于某个模板；
- 自定义目录；
- 已被用户修改。

从第一步进入第二步时执行目录初始化判断；普通返回不重复初始化。更换模板且目录已修改时进入覆盖确认流程。

确认页和导出数据均从当前表单、岗位映射和目录状态派生，不维护重复的展示副本。

## 13. 组件与文件边界

本次沿用现有单页实现方式，主要修改：

- `major-construction-platform/src/mock/research-report.ts`
  - 扩展报告与表单类型。
  - 新增专业、区域和模板配置。
  - 增加专业与行业模板目录。
- `major-construction-platform/src/App.vue`
  - 扩展创建状态、校验、目录初始化和动态正文生成。
  - 调整三步向导、确认页、生成失败态和报告库展示。
- `major-construction-platform/src/styles/80-report.css`
  - 增加新字段、多选岗位、创建方式、模板信息和错误状态样式。
- `major-construction-platform/index.html`
  - 同步静态入口中的数据、状态、表单、校验和交互。
- `major-construction-platform/tests/results-portal.test.mjs`
  - 增加 Vue 与静态入口的结构和状态测试。

如果实现过程中 `App.vue` 的报告逻辑明显影响可读性，可将纯数据转换与报告正文生成函数提取到报告专用工具文件，但不进行与本功能无关的拆分。

## 14. 响应式与可访问性

- 桌面端参数表单使用两列布局，报告名称、岗位和参考文件占满整行。
- 窄屏改为单列，操作按钮允许换行。
- 岗位标签可换行，长名称使用省略显示并提供完整标题。
- 单选、多选、错误提示和步骤状态具备可识别的标签与 ARIA 关联。
- 禁用选项不仅依赖颜色表达。
- 页面不出现横向溢出。

## 15. 测试与验收

### 15.1 功能测试

- 新建报告默认进入第一步。
- 专业报告和行业报告执行不同的专业必填规则。
- 所有公共必填字段能阻止无效提交。
- 岗位至少选择一个且不超过 10 个。
- 模板模式载入对应模板目录。
- 自定义模式只生成一个空白一级章节。
- 已修改目录更换模板前出现覆盖确认。
- 返回上一步不丢失参数、岗位、文件数量和目录。
- 空目录标题不能进入第三步。
- 第三步完整展示参数、岗位和目录摘要。
- 生成成功后进入报告编辑页。
- 生成成功只创建一条草稿记录，首次保存后状态变为已完成。
- 模拟生成失败时可以重试或返回配置。
- PDF 与 ADS 导出入口保持可用。

### 15.2 静态一致性

- Vue 入口和 `file://` 静态入口具有相同字段。
- 两个入口具有相同必填规则、岗位上限和创建方式行为。
- 两个入口均支持完整三步路径。

### 15.3 工程验证

- `npm test` 通过。
- `npm run build` 通过。
- 常用桌面宽度和窄屏宽度下无文字出框或横向滚动。
- 报告库、编辑、预览、PDF 和 ADS 既有测试不回归。

## 16. 完成标准

用户能够从报告库新建专业报告或行业报告，明确选择专业、行业、区域和最多 10 个分析岗位，选择模板目录或自定义目录，核对完整生成配置，并进入现有的生成、编辑与导出流程。生成后的报告和 ADS 文件能够反映本次选择的关键参数，Vue 与静态入口行为一致，测试和生产构建通过。
