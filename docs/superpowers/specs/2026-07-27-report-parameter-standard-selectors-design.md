# 报告参数标准化选择器设计

## 目标

精简“调研报告生成”的参数配置页，移除不需要用户决策的报告元数据，并将行业、地区和岗位范围改为符合实际调研场景的选择方式。

本次调整同时覆盖 Vue 应用入口与支持 `file://` 访问的静态入口，确保两种运行方式的字段、校验、保存和报告生成行为一致。

## 用户需求

- 参数页不展示“报告类型”。
- 分析岗位支持任意数量的多选，不设置 10 个上限。
- 参数页不展示“创建方式”和“报告模板”。
- “相关行业”使用可搜索选择器，数据口径采用现行的 GB/T 4754—2017《国民经济行业分类》。
- “分析区域”支持城市与经济区混合多选，不限制数量。

## 范围与兼容策略

### 本次修改

- 参数配置页的字段、交互、校验和提示。
- 第三步确认页中与已删除字段对应的摘要。
- 报告创建、编辑和再次生成时的行业与地区数据回填。
- 报告记录、生成元数据和动态报告正文对多地区数据的兼容。
- Vue 与静态入口的对应状态、事件和模板。
- 自动化行为测试、生产构建验证。

### 保持不变

- 三步向导结构：参数配置、目录调整、报告生成。
- 报告名称、专业、参考文件、目录编辑和报告生成流程。
- 报告库中既有历史记录的读取与预览。
- 既有报告目录的编辑能力。

### 内部兼容

“报告类型”“创建方式”“报告模板”不再作为新建报告时的用户输入，但暂时保留兼容字段：

- 新建报告使用固定的专业报告兼容值。
- 目录直接使用当前默认目录，不再根据创建方式或模板切换。
- 读取旧报告时继续接受旧的 `reportKind`、`creationMode` 和 `templateId`。
- 新界面、校验和确认摘要不展示这些兼容字段。

这样可以在不迁移全部历史模拟数据的前提下移除多余决策，并降低对报告库、预览和生成链路的影响。

## 界面设计

### 参数布局

参数页按以下顺序排列：

1. 报告名称。
2. 选择专业。
3. 相关行业。
4. 分析区域。
5. 选择分析岗位。
6. 参考文件上传。

“基本参数”的说明文字改为“设置报告对象与数据范围”，不再提及创建方式。

### 相关行业

相关行业使用单选搜索选择器：

- 输入行业编码或名称可过滤结果。
- 结果按 GB/T 4754—2017 的层级展示。
- 每项显示“编码 + 行业名称”，并标注门类、大类、中类或小类。
- 选择后，输入区显示行业编码与名称。
- 点击清除后恢复未选择状态。
- 表单保存行业编码和行业名称；报告正文默认使用行业名称，需要说明分类口径时同时显示编码。

标准数据随应用本地打包，Vue 与静态入口共享相同的数据口径，不依赖运行时网络。

### 分析区域

分析区域使用可搜索多选选择器：

- 选项分为“城市”和“经济区”两组。
- 搜索同时匹配名称、所属省级地区和类型。
- 城市与经济区可以混合选择。
- 已选项以标签展示，可逐项删除，也可清空全部。
- 不设置选择数量上限。
- 同一选项不能重复添加。

城市数据覆盖全国地级及以上城市。经济区采用产品内置的常用国家级区域集合，包括京津冀、长三角、粤港澳大湾区、成渝地区双城经济圈、长江中游城市群、关中平原城市群、北部湾经济区和海峡西岸经济区。后续扩展只需增加选项数据，不改变表单结构。

保存时使用稳定标识数组，同时保留显示名称，确保历史记录回填和报告生成不依赖选项顺序。报告正文将多个区域以“、”连接展示。

### 分析岗位

沿用当前岗位卡片列表：

- 移除最多 10 个的说明。
- 移除 `N / 10` 计数，改为“已选择 N 个”。
- 移除达到 10 个后的禁用状态。
- 移除超过 10 个的校验错误。
- 保留至少选择一个岗位的校验。

### 已删除字段

参数页完整移除：

- 报告类型。
- 创建方式。
- 报告模板。

第三步“报告信息”摘要同步移除报告类型和创建方式，只展示报告名称、专业、相关行业、分析区域、分析岗位和参考文件信息。

## 数据模型

### 行业选项

行业选项使用稳定结构：

```ts
interface StandardIndustryOption {
  code: string
  name: string
  level: 'section' | 'division' | 'group' | 'class'
  parentCode: string | null
}
```

报告表单增加 `relatedIndustryCode`，既有 `relatedIndustry` 字段继续保存行业名称，用于兼容现有生成逻辑。

### 地区选项

地区选项使用稳定结构：

```ts
interface ReportRegionOption {
  id: string
  name: string
  type: 'city' | 'economic-zone'
  province?: string
}
```

表单增加 `regionIds: string[]` 和 `regionNames: string[]`。既有 `region` 字符串继续保存由多个名称拼接的展示值，用于兼容报告库与现有生成逻辑。兼容加载逻辑把旧报告中的单个区域字符串转换为单元素数组。

### 序列化与生成

- 新报告记录保存行业编码、行业名称、地区标识和地区名称。
- 报告库的区域列将多个名称压缩为易读文本。
- ADS 元数据与动态报告正文使用规范化后的行业、地区数据。
- 旧记录缺少新增字段时，从既有字符串推导显示值，不中断编辑和预览。

## 状态与交互

搜索选择器使用页面内状态控制展开、关键词和候选结果：

- 打开一个选择器时关闭另一个选择器。
- 选择、清除或失焦后及时清除对应校验错误。
- Escape 关闭候选面板。
- 点击组件外部关闭候选面板。
- 键盘焦点、按钮标签和列表语义保持可访问。

静态入口使用事件委托实现相同行为，Vue 入口使用响应式状态与计算属性实现；两者使用一致的显示文案和数据常量。

## 校验与错误处理

进入目录调整前依次校验：

1. 报告名称非空。
2. 专业已选择。
3. 相关行业已从标准选项中选择。
4. 至少选择一个城市或经济区。
5. 至少选择一个分析岗位。

不再校验：

- 报告类型。
- 岗位选择上限。
- 创建方式。
- 报告模板。

编辑旧报告时，如果旧行业或地区不在新选项中，仍以兼容标签展示；用户主动重新选择后保存为标准化数据。

## 测试设计

### 工具函数测试

- 行业搜索能按编码和名称匹配，并保留层级信息。
- 地区多选能混合城市与经济区、去重并删除。
- 旧的单区域字符串可规范化为数组。
- 任意数量岗位通过上限校验，零岗位仍返回必选错误。
- 删除字段不会再触发报告类型或模板校验。
- 生成元数据正确输出行业编码与多个区域名称。

### 页面行为测试

Vue 与静态入口都需验证：

- 参数页不出现报告类型、创建方式和报告模板。
- 行业选择器支持搜索并选中标准行业。
- 地区选择器支持城市和经济区混合多选。
- 选择超过 10 个岗位时仍可继续选择。
- 岗位提示只显示已选数量，不出现 `/ 10` 或“最多选择 10 个”。
- 确认页只展示保留字段，并正确显示多个区域。

### 完整验证

- 运行报告生成相关聚焦测试并确认先失败后通过。
- 运行全部 Node 测试。
- 运行 TypeScript 检查与 Vite 生产构建。
- 检查 Vue 与静态入口中不存在已删除字段的生产模板或旧上限逻辑。
