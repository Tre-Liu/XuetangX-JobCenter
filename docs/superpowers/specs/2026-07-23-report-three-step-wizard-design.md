# 报告生成三步向导设计

## 1. 背景

当前“报告生成”创建页把报告参数、报告维度和目录结构同时铺在一个页面中。左侧参数区宽度较窄，维度卡片中的中文容易拥挤；右侧目录较长，页面主任务也不够聚焦。

本次将报告创建过程拆分为三个连续步骤：

1. 参数配置
2. 目录结构调整
3. 报告生成

改造只调整创建报告的前端流程和布局。报告库、生成进度、报告编辑、PDF 预览与导出能力保持现有实现。

## 2. 目标

- 让用户一次只处理一个明确任务。
- 通过轻量步骤条展示当前位置和完成进度。
- 给参数、维度和长目录提供足够的展示空间。
- 避免标题、文件名、维度说明和目录名称越出容器。
- 在真正生成前提供完整的只读摘要，减少误操作。
- 保持 Vue 页面与 `file://` 静态入口功能一致。

## 3. 非目标

- 不新增或调整后台接口。
- 不改变报告参数、维度和目录的数据结构。
- 不重做报告库、报告编辑器、预览和导出页面。
- 不实现跨会话草稿持久化。
- 不引入新的 UI 组件库。

## 4. 方案选择

### 4.1 采用方案：创建页内部三步向导

保留现有 `currentReportView` 顶层状态，在 `create` 视图内部新增步骤状态。每一步占据完整工作区，页面顶部使用紧凑步骤条，底部使用稳定的上一步/下一步操作区。

选择原因：

- 与现有报告库、生成、编辑和预览状态兼容。
- 参数和目录数据不需要搬迁或重新建模。
- 每一步可以独立控制布局和校验。
- 返回上一步时可自然保留已填数据。

### 4.2 未采用方案：拆分为多个顶层视图

把参数、目录和确认页都加入 `currentReportView` 会让顶层状态承担过多职责，并增加从编辑页返回配置时的状态判断。

### 4.3 未采用方案：同页折叠卡片

在同一长页面中展开和折叠三步虽然便于回看，但长目录仍会拉长页面，当前任务不够聚焦，底部生成操作也容易远离上下文。

## 5. 页面结构

### 5.1 共用区域

创建页从上到下由四部分组成：

1. 页面标题与“返回报告库”按钮。
2. 高度约 44px 的轻量步骤条。
3. 当前步骤的独立内容工作区。
4. 底部操作区。

步骤条不使用大面积装饰，不抢占页面标题层级。当前步骤使用主色实心圆，已完成步骤使用勾选状态，未完成步骤使用中性描边状态。

底部操作区与内容区之间使用分隔线。第 2、3 步提供“上一步”，第 1、2 步提供“下一步”，第 3 步提供“AI 开始生成报告”。

### 5.2 第 1 步：参数配置

内容区分为上下两个卡片。

“基本参数”卡片包含：

- 报告标题
- 报告类型
- 产业方向
- 参考文件上传

报告标题占满一行。报告类型和产业方向在桌面端使用两列布局，窄屏改为单列。上传文件名过长时在文件列表中省略显示，完整文件名通过标题提示提供。

“选择报告维度”卡片位于基本参数下方。桌面端使用两列维度卡片，窄屏使用单列。标题和说明允许自然换行，不使用强制单行。

进入下一步前必须满足：

- 报告标题去除首尾空格后不为空。
- 至少选择一个报告维度。

校验失败时停留在第 1 步，并在对应区域显示清晰提示。

### 5.3 第 2 步：目录结构调整

目录编辑器独占主要工作区。保留现有三级目录、新增章、新增子项、修改标题和删除能力。

目录区域设置明确的最大可视高度并在内部滚动，使底部操作区保持可见。目录标题输入框使用 `min-width: 0` 和容器宽度约束，不越出操作按钮区域。

目录至少保留一章。仅剩最后一章时禁用该章的删除操作，避免进入空目录状态。

### 5.4 第 3 步：报告生成

第 3 步是生成前的只读确认页，包括：

- 报告信息：标题、类型、产业方向、参考文件数量。
- 生成范围：已选择维度数量和维度标签。
- 目录摘要：章、节、三级条目的数量，以及前两章名称。
- 生成说明：完成后将进入可编辑报告页。

目录摘要提供“查看全部”，用于回到第 2 步检查目录。页面主按钮为“AI 开始生成报告”。

点击主按钮后进入现有 `generating` 视图。生成完成后进入现有 `editor` 视图。

## 6. 状态与数据流

### 6.1 顶层状态

现有 `currentReportView` 保持以下状态：

- `library`
- `create`
- `generating`
- `editor`
- `preview`

### 6.2 创建步骤状态

创建页新增：

```ts
type ReportCreateStep = 1 | 2 | 3
const reportCreateStep = ref<ReportCreateStep>(1)
```

新建报告时重置为第 1 步。参数、维度、目录继续使用现有的 `reportForm`、`selectedReportDimensions` 和 `reportTocRows`。

### 6.3 导航规则

- “下一步”先校验当前步骤，通过后才更新步骤状态。
- 用户不能直接跳到未完成的后续步骤。
- 已完成步骤可通过步骤条直接返回。
- 返回修改参数或目录时，其他步骤的数据不清空。
- 从报告编辑页点击“返回配置”时进入 `create` 视图的第 3 步。
- 第 3 步“查看全部”进入第 2 步。

### 6.4 摘要计算

第 3 步摘要从当前状态实时计算：

- 文件数量来自当前上传控件状态。
- 维度标签来自 `selectedReportDimensions` 与维度定义的映射。
- 章、节和三级条目数量来自当前目录树遍历结果。

摘要不保存独立副本，避免与实际生成配置不一致。

## 7. 视觉与响应式约束

- 步骤条高度约 44px。
- 内容卡片沿用现有报告页圆角、描边和主色。
- 表单控件高度约 38–40px。
- 卡片内边距约 18–20px。
- 正文最小字号不低于现有报告页的 12px。
- 中文标题和说明允许自然换行。
- 需要保持单行的文件名和辅助信息使用省略号，并提供完整内容提示。
- 所有栅格子项设置 `min-width: 0`。
- 目录工作区内部滚动，页面底部操作不被长目录推离。
- 窄屏下表单和维度卡片切换为单列，步骤名称保持简短。

## 8. 生成与异常状态

- 生成按钮点击后立即进入忙碌状态，防止重复提交。
- 生成过程继续使用现有生成进度页面。
- 本次不新增真实生成失败分支；现有模拟生成行为保持不变。
- 返回报告库沿用现有行为，不新增未保存确认弹窗，因为当前创建流程没有持久化草稿。

## 9. 可访问性

- 步骤按钮使用真实 `button` 元素。
- 当前步骤使用 `aria-current="step"`。
- 未完成且不可跳转的步骤使用禁用状态。
- 校验提示与对应字段建立可读关联。
- 所有图标按钮保留明确的 `title` 或可访问名称。
- 键盘用户可以依次聚焦步骤、表单、目录操作和底部按钮。

## 10. Vue 与静态入口同步

Vue 实现在 `major-construction-platform/src/App.vue` 中完成，样式写入现有报告样式文件。

静态入口 `major-construction-platform/index.html` 同步实现：

- 创建步骤状态
- 三步页面渲染
- 步骤导航事件
- 参数校验
- 第 3 步摘要
- 返回编辑配置时定位到第 3 步

两种入口使用相同的中文文案和步骤顺序。

## 11. 测试与验收

### 11.1 自动化测试

相关测试至少覆盖：

- 新建报告默认显示第 1 步。
- 步骤条顺序为参数配置、目录调整、报告生成。
- 报告标题为空时不能进入第 2 步。
- 未选择维度时不能进入第 2 步。
- 合法参数可以进入第 2 步。
- 第 2 步修改目录后进入第 3 步。
- 返回第 1、2 步时已填数据保留。
- 第 3 步摘要反映当前参数、维度和目录。
- 点击生成进入现有生成流程。
- 编辑页返回配置时定位到第 3 步。
- Vue 与静态入口保留一致的关键文案和交互入口。

### 11.2 工程验证

- 运行相关 Node 测试。
- 运行 TypeScript/Vue 类型检查。
- 运行生产构建。
- 在实际页面中检查三个步骤。

### 11.3 视觉验收

- 步骤条不超过页面标题的视觉层级。
- 所有标题、说明、标签和按钮文案均不出框。
- 维度卡片在常用桌面宽度下不出现文字挤压。
- 目录变长后只在目录区滚动。
- 底部导航始终容易发现。
- 窄屏下无横向溢出。

## 12. 验收结果定义

用户可以从报告库进入新建报告，依次完成参数配置、目录调整和生成前确认；系统在必要位置进行校验并保留已填数据；用户确认后进入现有生成和编辑流程。Vue 页面与静态入口均可完成同一条三步路径，且在常用页面宽度下不存在文字出框和横向溢出。
