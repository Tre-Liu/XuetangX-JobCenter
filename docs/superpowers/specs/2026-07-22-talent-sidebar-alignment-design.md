# 人才方案管理侧边栏对齐产教模型设计

## 背景与目标

人才方案管理当前使用“模块标题 + 平铺栏目 + 底部工具入口”的侧边栏结构。与产教模型已经采用的“图标化分组标题 + 紧凑子菜单”相比，现有层级较弱，方案建设、方案调研和方案比对之间的关系不够清晰。

本次优化保留全部现有入口、状态和页面内容，仅调整侧边栏的信息层级与视觉表现，使其与产教模型处于同一设计体系，并保证 Vue 入口与用户截图所使用的 `file://` 静态入口一致。

## 范围

### 包含

- 将人才方案管理侧边栏重组为“方案建设”“方案调研”“方案比对”三组。
- 保留 `2026版本` 选择器和现有七个页面入口。
- 对齐产教模型侧边栏的宽度、渐变背景、图标尺寸、菜单密度、选中态和组间节奏。
- 补充悬停、键盘聚焦与内部滚动状态。
- 同步修改 Vue 模板和 `file://` 静态模板。
- 更新相关结构测试并完成两种入口的视觉与交互验证。

### 不包含

- 不修改人才方案页面主体内容、空状态或弹窗。
- 不新增、删除或重命名现有页面入口。
- 不改变 `activeTalentSection`、`activeTalentSubsystem` 等状态语义。
- 不实现新的版本切换业务逻辑。
- 不调整产教模型侧边栏本身。

## 信息架构

侧边栏按照以下顺序展示：

1. **方案建设**
   - 2026版本
   - 培养目标
   - 毕业要求
   - 课程管理
   - 支撑矩阵
   - 学生管理
2. **方案调研**
   - 人才培养方案调研
3. **方案比对**
   - 人才培养方案比对

“方案建设”在任一人才方案栏目处于活动状态时高亮；“方案调研”和“方案比对”分别在对应子系统打开时高亮。每个时刻只显示一个活动子菜单项。

## 视觉设计

### 容器

- 侧边栏固定宽度为 `176px`，不随内容页变化。
- 使用与产教模型相同方向和明度的浅蓝至浅紫渐变背景，并保留右侧弱边界。
- 水平内边距为 `24px`，可用菜单宽度为 `128px`。
- 当窗口高度不足时，侧边栏自身纵向滚动，不推动主内容区滚动。

### 分组标题

- 每组由 `34px × 34px` 的图标、组标题和子菜单构成。
- 图标采用项目现有 CSS 图标语言，不新增外部资源或网络依赖。
- 标题使用现有中文界面字体栈，字号、字重与产教模型一级分组保持一致。
- 三组之间使用稳定的垂直间距，不再依赖 `margin-top: auto` 将调研与比对入口压至底部。

### 版本选择器与菜单项

- 版本选择器和子菜单均为 `128px` 宽、`30px` 高、`8px` 圆角。
- 默认状态使用半透明白色背景和柔和的灰蓝文字。
- 活动状态使用蓝紫渐变背景、白色文字与柔和阴影。
- 悬停状态提高背景不透明度并轻微增强文字颜色，不改变布局尺寸。
- 键盘聚焦使用清晰的蓝色外轮廓，避免只依赖颜色表达焦点。
- 长标签保持单行，字号与内边距确保“人才培养方案调研”和“人才培养方案比对”完整显示。

## 组件与代码结构

### Vue 入口

- 在 `major-construction-platform/src/App.vue` 中将人才方案侧栏改为三个语义分组。
- 继续使用 `sideItems`、`talentSubsystemItems`、`selectTalentSection()` 和 `openTalentSubsystem()`。
- 新增人才方案专属样式类，不直接复用带有业务含义的 `job-*` 类，避免两个模块在后续迭代中互相耦合。

### 静态入口

- 在 `major-construction-platform/index.html` 的 `staticTalentShell()` 中输出与 Vue 相同的三组结构和样式类。
- 保留 `data-talent-section` 与 `data-talent-subsystem`，继续使用现有事件委托和渲染函数。
- 静态入口与 Vue 入口使用同一份 CSS，避免重复定义视觉参数。

### 样式

- 在 `major-construction-platform/src/styles/20-talent.css` 中增加人才方案专属侧栏规则，使其靠近产教模型参考样式并共享相同的尺寸与色彩参数。
- 必要时在 `10-shell.css` 中保留通用侧栏基础规则，但人才方案的最终样式必须通过更具体的模块类控制，避免被 `50-dialogs.css` 中的通用响应式覆盖意外改变。

## 状态与交互

- 点击五个方案建设入口时，清空 `activeTalentSubsystem` 并更新 `activeTalentSection`。
- 点击方案调研或方案比对时，保留现有子系统打开逻辑，并取消方案建设子项的活动样式。
- 组标题仅表达层级和所属活动状态，不承担导航或折叠；用户仍通过现有七个入口切换页面，三个分组始终可见。
- 未知子系统键继续沿用现有兜底逻辑，不引入新的错误页面。
- 本次不产生网络请求，也不新增加载或失败状态。

## 可访问性

- 所有七个页面入口继续使用原生 `button`，分组标题使用非交互语义容器。
- 活动菜单项通过类名和 `aria-current="page"` 同时表达。
- 组标题与子菜单使用清晰的语义容器和可读标签。
- 聚焦态在浅色和渐变背景上均具有足够可见度。
- 减少动态效果偏好开启时，不使用位移型过渡。

## 验证方案

### 自动化检查

- 更新 `major-construction-platform/tests/results-portal.test.mjs`，断言 Vue 和静态模板均包含三个分组、七个入口和人才方案专属样式类。
- 断言侧栏宽度为 `176px`、菜单宽度为 `128px`，并存在蓝紫活动态与滚动规则。
- 运行 `npm test` 和 `npm run build`。

### 交互检查

- 在 Vue 入口依次点击五个方案建设栏目、方案调研和方案比对，确认内容、活动项和组标题同步切换。
- 在 `file://` 静态入口执行相同点击路径，确认行为一致。
- 使用键盘 Tab 导航检查聚焦顺序和焦点可见性。

### 视觉检查

- 在与参考截图一致或等比例的桌面视口中分别截取人才方案和产教模型侧边栏。
- 对比宽度、背景、分组图标、标题层级、菜单尺寸、选中态和纵向节奏。
- 在较矮视口确认侧边栏内部可滚动，且主内容区域没有横向位移。

## 验收标准

- 三个分组及七个入口在 Vue 和静态入口中完整可见、可操作。
- 侧边栏视觉语言与产教模型一致，同时保留人才方案管理的业务标签。
- 任何入口切换后仅有一个子菜单项处于活动状态，所属组标题同步高亮。
- 不影响人才方案主体页面、弹窗、其他顶级模块或现有路由状态。
- 自动化测试和生产构建通过，视觉检查无高、中优先级问题。
